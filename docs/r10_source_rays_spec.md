# R10-S: 원본 직선·화살촉 관측

## 결정과 경계

O+C까지 실제 PPT 육안 확인: 중복 3개 제거와 무방향 트리 6개 연결 복원은 유효하지만, directed tree의 누락은 해결되지 않았다. dilated component의 가장자리 최단경로와 너비를 사용하면 직선이 꺾인 경로가 되고 화살촉 대비가 약해진다. 이를 writer 오차 확대나 정답 관계 주입으로 우회하지 않는다.

새 연구 경로는 RGB와 기존 label-anchor bbox만으로 모든 후보 쌍의 직선 근거를 조사한다. 기존 C-v2는 변경하지 않는다. O+C를 기준으로 원본 화살촉이 확실한 쌍만 추가/대체한다. 기존 owner ID/bbox/label은 보존한다. GT, annotation, PPT는 생성 과정 입력으로 금지한다. 실제 15개는 이미 본 개발 진단이며 일반화 승인 자료가 아니다.

## 초기 관측 계약

- s=이미지 높이/360. 범위는 밝은 배경의 어두운 직선과 두 label-anchor이며, 겹친 owner 쌍은 제외한다.
- bbox 중심선 주변 8s 폭의 원본 stroke 후보 중 중앙 20~80%로 TLS 축을 제안한다. 원본을 팽창하거나 gap repair한 mask로 지지율을 계산하지 않는다.
- 제안 축은 두 bbox를 모두 통과해야 한다. 양쪽 안쪽 교점 사이가 최소 24s이며 제3 owner bbox를 가로지르면 기권한다.
- 중앙 shaft는 p95<=3s, 최대 잔차<=3s, pixel-cell projection 지지율>=.95, 최대 공백<=2s. 근처 다른 획 때문에 이를 만족하지 못하면 기권한다.
- 끝점 쪽은 축 근처 원본 획의 횡단 폭을 관측한다. shaft 대비 넓어짐과 tip 쪽 taper가 함께 있는 한쪽만 방향 후보다. 양끝 경쟁, 횡단 막대, 분리된 점, 사각형, 평행선, 굽은 선은 음성 대조다. 끝점 연장은 원본 지지 끝에서 8s 이하로 제한한다.
- OCR 문자/owner 점수/트리 의미/위아래 순서는 방향 근거가 아니다. 양방향 화살표와 곡선은 초기 범위 밖이다.
- 문턱값·관측 방식은 합성 대조 개발 기록과 Git revision으로 추적한다. 실제15 실행 전 테스트·코드 SHA를 잠근다. 실패를 지우거나 명세 수정을 이전 PASS로 소급하지 않는다.

## 검증

실제 RGB 선/삼각 화살촉을 독립 rasterizer로 생성하여 방향·회전·크기·순서에 대해 확인한다. plain line, gap, elbow, parallel, third owner, T 막대, 한쪽 점을 반드시 포함한다. 이후 실제15는 별도 출력 디렉터리에서 이미지 단독 추론, native render, 별도 정답 평가, 전체 contact 및 트리 확대 육안 검토 순서로 진행한다. 이 단계는 사람 편집시간 측정이나 프로덕션 승인과 동일하지 않다.

## 실제15 실행 전 기본 대조 개발 기록

초기38개 중30통과/8기권. .75배에서 점을 좁은 bin으로 세면 실제 연속 획에 빈 bin이 생기는 4건은 물리 pixel-cell 투영 겹침으로 수정했다. 회전30/60도에서 OpenCV width3의 최종 획은 폭 약5픽셀이고 p95약2.35라 초기2s gate를 넘는 4건이 있었다. 원본 폭 지원범위를3s로 명시 변경했으며 최대잔차3s는 유지한다. 이들은 1픽셀 시각 실패가 아닌 관측 지원범위/구현 문제다. 회전된 화살촉 base가 두 bin에 나뉘는 경우는 이전 두 bin에서 증가를 조사한다. 수정후 기본38/38. 독립 반례는 별도로 추가하며 이 기록을 실제15 성적으로 해석하지 않는다.

현재 terminal 폭은 끝16s를 max(.75,s) 간격으로, 물리 pixel-cell과 겹치는 획의 횡단 범위로 계산한다. peak는 shaft 대비1.6배 및+2s 이상, taper3~12개 bin, 마지막 폭<=peak의.75와shaft+s, 감소상관<=-.8, 이전2bin 중 최소폭<=peak의.85, 양옆 각각 peak의.2 이상이어야 한다. 폭 증가만 있는 막대/원형점은 기본대조에서 기권한다. 양끝 중 정확히 한쪽만 지원되어야 한다. 기존 화살표와 방향충돌하면 덮어쓰지 않는다.

### 독립 대조 후 수정

별도 Pillow rasterizer990 PNG(690 unique RGB), 순서 포함1980판정에서 접촉 계약위반126, 양방향을 단방향으로 축소24, positive기권42를 발견했다. unique RGB로는 각각21/4/7이다. 접촉은 방향오답 확정이 아니라 사전 기권계약 위반이며 double은 실제 방향정보 소실이다. 이 최초 결과를 보존한다.

수정: 반대쪽도 충분히 넓어져 화살촉 가능성이 있으면, 완전 taper 검사를 통과하지 못했더라도 단방향을 확정하지 않는다. 화살촉 쪽 끝16s에서는 횡단 corridor로 자르기 **전** 원본 connected component가 폭8s 바깥으로 이어지는지 확인한다. 접촉 획을 잘라내고 깨끗한 tip이라고 판단하지 않는다. 마지막 폭의 shaft 대비 허용량은 방향별 물리 pixel-cell 투영폭 `abs(ux)+abs(uy)`로 수정한다. 이는 scale이 아닌 원본 한 pixel의 횡단 지지폭이며, 회전/작은 그림에서 실제 terminal 폭과 area/span shaft 폭이 다르게 양자화되는 것을 반영한다. 원15 결과를 보고 고친 수치가 아니다.

통합 경계 대조는 추가로 owner bbox 안의 반대 화살촉을 제외하거나 제3 bbox로 접촉 획을 지워 관측이 부당하게 확정되는 결함을 찾았다. 원본 raw mask에서 owner 내부를 더 이상 지우지 않는다. 중앙 shaft와 동일 원본 CC가 어느 owner의 깊은 내부로 이어지면 기권한다. 깊이는 bbox 경계에서 원본1pixel보다 안쪽이다. 최초 경계 접촉 veto는 기본 대조8개를 추가기권했지만, 실제 침범은 1~3pixel의 중심이 경계 안으로 .10~.51px 들어간 경우였다. 이를 숨은 화살촉 본체나 글자 손실로 분류하지 않는다. 1pixel band는 경계 양자화로 별도 취급하고 연결된 내부 본체는 계속 보호한다. 기존 결과를 다시 써서 PASS로 바꾸지 않는다.

좌표 일관성: S의 TLS/물리cell 투영과 같은 정수 raster 좌표를 owner contact에도 사용한다. 초기 contact만 +.5를 더한 혼용을 제거했다. D-v3 bbox pixel-center convention을 다른 모듈에 그대로 이식하지 않는다. 1pixel 경계 band는 이 정수 좌표에서도 유지한다.

### 분기 근처 혼합 관측 수정

실제 첫 S-v1/v2는 모두35TP/2FP/32FN으로014의대각선2개를 추가 복원했지만012는 그대로였다. 폭 corridor 안의 모든 획을 한 화살촉 폭으로 세면, 원본에서는 떨어져 있는 다른 가지/글자도 같은 획처럼 섞인다. 임시 반대끝 gate를 느슨하게 만들지 않고, shaft 중앙을 구성하는 **원본 8-connected component가 정확히 하나일 때 그 전체 component만** terminal 관측 대상으로 삼는다. 원본에서 붙어 있는 contact/double은 계속 같은 component로 남아 보호된다. 분리된 shaft 조각/경쟁 component는 이 경로에서 기권한다. 이 변경은 새로운 source SHA와 같은 독립/통합 대조로 재검증한다.

같은component 관측 후 실제15는43TP/2FP/24FN으로 개선되었다. tree00149의9개 연결과tree00036의5개를 원본근거로 복원했고 owner/text는 불변이다. tree00036의남은1개는 평평한 화살촉 base의 폭7.81/7.81/7.96에서 마지막값을peak로고르면 앞쪽폭증가를놓치는문제다. peak를수동지정하지않고, 최대폭에서물리반pixel-cell 이내인연속구간의시작을base로정의한다. 기본/독립 반례를 같은조건으로 재검증한다.
