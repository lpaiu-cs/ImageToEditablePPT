# R10-G: 원본의 닫힌 노드 윤곽 검증

## 관측에서 출발한 문제

fresh RGB 15개를 PowerPoint로 다시 렌더링한 결과, 원형 그래프 노드가 사각형으로 나오고 일부 박스 테두리는 거의 사라졌다. 검출 모델은 ellipse 클래스를 학습하지 않았고, 현재 스타일 추정은 부정확한 검출 bbox 경계의 2px 띠 중앙값을 사용한다. bbox 오차만으로 테두리 대신 배경색이 선택된다. 이것은 1px 복제 오차 문제가 아니라 다른 도형/보이지 않는 윤곽이라는 실용 문제다.

## 제한된 수정 계약

- 이미 검출된 node box/rounded_box/ellipse만 관측한다. 새로운 노드, 컨테이너, 연결, 텍스트는 만들지 않는다.
- 원본 stroke mask의 **실제로 닫힌 내부 hole**만 후보로 삼는다. contour를 인위적으로 닫거나 dilation으로 열린 선을 연결하지 않는다. 연결된 외부 화살표의 끝까지 노드 윤곽으로 삼지 않는다.
- 후보의 면적과 네 bbox 끝이 검출 범위와 일치해야 하고 후보가 정확히 하나여야 한다. 텍스트 글자의 작은 구멍은 면적 조건으로 제외한다.
- bbox 비교는 축별 `max(4 원본 px, 해당 축 길이의 5%)`다. 가로로 긴 박스의 가로 오차를 짧은 높이로 제한하지 않는다. 이는 검출 후보와 관측 윤곽의 동일성 범위이며 새 윤곽을 창작하는 허용 오차가 아니다.
- 축 정렬 ellipse는 둘레 전체의 정규화 반지름 잔차와 각도 지지율로 확인한다. 사각형/둥근 사각형과 분리되지 않으면 종류를 바꾸지 않는다. 회전 타원/불완전 윤곽은 기권한다.
- 색은 이 닫힌 내부와 그 바로 바깥의 실제 ink만으로 관측한다. 박스 바깥 bbox 띠 중앙값으로 대신하지 않는다. 검증되지 않은 노드는 채움을 추가하지 않는다.
- ID, 검출 bbox, OCR 라벨, 연결은 보존한다. 수정은 확인된 node kind와 시각 스타일뿐이다. 연결 형상 개선은 별도 B 계약이다.

## 검증

실제 RGB 합성 대조에서 원/타원/사각/둥근 사각, 여러 크기·배경·선색·선두께·bbox 오차·외부 연결·내부 글자를 점검한다. 열린 호/열린 박스/교차선/그림자만 있는 영역은 닫힌 노드로 승인하지 않아야 한다. 독립 검출 15개는 개발 자료이며 기존 주석의 잘못된 box kind를 정답으로 튜닝하지 않는다. 변경 후 PowerPoint 렌더를 직접 확인하고 kind 점수 변화와 육안 의미를 구별한다.
