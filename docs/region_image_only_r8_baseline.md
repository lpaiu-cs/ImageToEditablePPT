# R8: 공통 PPT 렌더 정답쌍의 이미지 단독 기준선

## 판정

**주석 없는 기준선 재현 완료, 품질 미달. 제품 승격 없음.** 학습 트랙과 같은
실제 PPT 렌더 15개를 사용해, 기존 R6 region 경로의 최종 editable PPT를 평가했다.
새 알고리즘 성과가 아니라 두 트랙을 같은 입력에서 연결하기 위한 출발점이다.

## 입력 경계

- 학습 트랙의 `artifacts/ml-image-only-v1/rgb_inputs.json`에 있는 15개 ID/이미지
  SHA를 모두 검증했다. PNG를 별도 폴더에 `000.png`~`014.png`로 복사해 이름에 있는
  family 힌트도 실제 변환 함수에 전달하지 않았다.
- 추론은 원본 RGB와 고정 전체 ROI `[0,0,1,1]`만 받는다. 선택적 ROI 지원 API를
  사용했지만, 이번에는 사람이 영역을 따로 고르지 않았다. OCR·스타일 샘플링은 켰다.
- 원본 PPT/annotation/정답 역할/제외 마스크는 추론에 전달하지 않았다. 모델 checkpoint도
  사용하지 않는 기존 기하 기준선이다. R5 승인 v0.3과 구별해 R6 기준선으로 표시했다.
- 샘플마다 별도 Python 추론 프로세스를 실행하고 파일 읽기 허용 목록을 설치했다.
  입력 이미지·코드·Python 환경·폰트·자신의 출력 외 읽기는 거부한다. GT와 이름을 바꾼
  정답 파일도 거부하는 음성 대조 테스트를 추가했다. 실제 15개 변환은 모두 완료했다.
- **이 장치는 Python `open` 감사이지 OS 샌드박스가 아니다.** native 라이브러리의
  모든 파일 접근까지 증명하지 않는다. 실제 호출 경로/인자 확인과 함께 해석한다.
- GT는 변환 완료 후 별도 evaluator에서 읽었다. evaluator는 추론 코드에 import되지 않는다.

## 집합의 한계

이는 독립 승인 집합이 아닌 기존 합성 validation 개발 진단이다. 학습 작업이
mixed 560개를 감사하면서 원본 기하의 분할 중복과 근접 렌더 후보를 발견했고,
실제 렌더 val 21개 중 학습 근접 후보 6개를 제외한 15개를 제안했다. 이쪽에서
15개 입력 SHA는 직접 검증했으나 560개 누출 감사 전체를 독립 재실행하지는 않았다.
기존 checkpoint의 validation 선택 노출도 있어 미관측 일반화 성적으로 취급하지 않는다.
Phase16 locked holdout은 사용하지 않았다.

## 측정 결과

원본 픽셀 좌표, IoU 0.5 이상의 일대일 탐욕 매칭이다. 실제 출력 객체에 검출기용 NMS를
다시 적용하지 않았다. 따라서 학습 트랙의 detector postprocessing 점수와 완전히 동일한
측정 경계는 아니며, 단순히 두 F1을 대조해 승자를 정하면 안 된다.

| 항목 | TP | FP | FN |
|---|---:|---:|---:|
| 노드 위치·역할 | 63 | 5 | 28 |
| 노드 위치·역할·도형 종류 | 32 | 36 | 59 |
| 컨테이너 위치·역할 | 4 | 3 | 7 |
| 컨테이너 위치·역할·종류 | 1 | 6 | 10 |
| 추적 관계 | 22 | 8 | 45 |
| 최종 native 관계 | 16 | 2 | 51 |

관계는 양 끝 소유 객체와 방향/무방향/양방향을 함께 비교하며, 중복 관계도 개수에 포함했다.
관계 정답은 67개다. 출력 단계에서 거짓 경로 6개뿐 아니라 올바른 경로 6개도 누락됐다.
그래서 추적 개선과 native 표현 개선을 별도 측정해야 한다.

매칭된 노드 63개 중 OCR은 공백·대소문자 정규화 후 61개 일치, 2개 공백, 0개 오류다.
**이 수치 밖에 거짓 객체 위 라벨 3개가 더 있다.** 따라서 결과 전체에 OCR/소유 오류가
없다는 뜻이 아니다. 미매칭·누락 노드도 정답 전체 91개에 대한 실패로 남는다.

## 육안 확인

PowerPoint로 15개 PPT를 직접 열어 렌더했고, 모든 원본/출력 비교를 확인했다.

- 단순 block-flow는 박스와 라벨이 유용하지만 사선 분기가 빠졌다. 파란 분기 사례는
  박스만 남고 연결이 모두 빠졌다.
- cycle 사례는 원본에 없는 큰 타원과 여러 노드의 텍스트가 합쳐진 라벨을 출력했다.
  이미지 단독 객체 정체성/소유 관계가 해결되지 않았다는 명확한 실패다.
- graph 사례에는 잘못된 배경 객체와 라벨 소유 오류가 있다. `graph_1302_00063`은
  최종 관계 3개 중 2개가 방향/소유 관계 기준으로 틀렸다.
- 일부 layered stack은 직접 사슬을 보존하지만 다른 샘플은 노드를 컨테이너로 분류해
  라벨과 연결이 빠졌다. 종류 오류를 위치 점수로 숨기지 않는다.
- 두 카드형 matrix는 대체로 배치/라벨이 남는다. 테두리·폰트·채움 단순화는 별도 남아 있다.
- 텍스트만 있는 tree 3개는 모두 공백이다. 닫힌 윤곽 중심 후보 생성의 범위 한계다.

native 객체 ID/커넥터 소유자 바인딩과 래스터 객체 0개도 확인했다. 이는 편집 객체
직렬화 검증이지 시각·구조 품질 승인이나 사람의 수정 시간 절감 증거가 아니다.

## 병행 트랙과 다음 통합

학습 작업은 기존 checkpoint의 7-class head와 현재 코드의 8-class 계약 불일치를
발견해 잘못된 초기 평가를 무효로 보존했다. 옛 label 순서를 복구한 결과와 제한 pilot의
미채택 결과를 공유했으며, 자세한 검증은 그 작업의 별도 기록을 기준으로 한다.
현재 모델의 높은 검출 수치도 라벨/연결/native 전체 성공으로 확대하지 않는다.
학습 작업의 확정 커밋은 `7bb2beddcd50ffd65146082a6f82947f3a2613e1`이다.
무효인 것은 매핑 이전 평가와 Target 7 오류로 중단된 시도다. 매핑을 적용한
12-step pilot 자체는 유효하게 완료했으며, 개선이 없어 미채택한 것이다.

다음 통합은 **클래스 계약을 명시한 실제 ML 예측 객체 → 구조/연결/OCR/native 출력**이다.
정답 객체를 다시 공급하는 실험으로 돌아가지 않는다. 우선 같은 15개에서 레거시 label
adapter와 source SHA/좌표 계약을 확인한 예측 산출물을 받아 비교한다. 특히 텍스트
노드와 컨테이너 분류를 보존하고, 중복 OCR 소유와 사선/native 누락을 별도 분석한다.
checkpoint에는 class-map과 생성 코드 SHA를 함께 보존해야 하며, 기존 값이 없으면
복구 근거와 남는 불확실성을 기록한다. 이 통합 실험은 아직 이번 기준선에 포함되지 않았다.

## 재현·증거

- 실행: `tools/run_region_rgb_baseline.py` (`run`은 RGB manifest만 받음)
- 평가: `tools/evaluate_region_rgb_baseline.py` (GT evaluator manifest만 별도로 받음)
- 읽기 경계: `research/image_only_guard.py`, `tests/test_image_only_guard.py`
- 동결 요약: `benchmarks/region_r8_shared_rgb_baseline.json`
- 결과: `artifacts/region-image-only-r8/shared-val-baseline/`
- 육안 비교: 같은 경로의 `review/contact-0.png`~`contact-2.png`

프로덕션 region/CLI 파일은 바꾸지 않았다. 입력·런타임·실행기 해시는 실행 전에,
평가·렌더 해시는 실행 후 결속했다. 기존 산출물 덮어쓰기는 거부한다.
현재 체크아웃의 전체 테스트는 345개 통과, 기존 경고 9개다. 학습 작업의 별도
추가 테스트 수를 합쳐 이 체크아웃에서 실행한 것처럼 보고하지 않는다.
