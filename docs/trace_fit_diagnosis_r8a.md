# R8-A 후속 진단: 곧은 원본 선이 native fitting에서 탈락하는 이유

## 결론

`tree_1302_00079`의 탈락 대각선 6개는 원본 RGB에서 곧은 선인데, 현재 추적은
연결 확인용으로 복구·팽창한 마스크 위 경로를 따라간다. 그 경로가 원본 선의 중심에서
벗어나고 예측 owner 경계에 투영되는 끝부분에 작은 가로/세로 꺾임이 생긴다.
원본 RGB와 경로를 겹쳐 직접 확인했다. **native writer의 직선 지원 부재가 아니라
관측 경로와 출력 적합 경계 사이의 문제**다. 4px 기준을 완화하거나 경로를 교체한
후보를 실행한 결과는 아니다.

## 재현 경계

- 동결 A-T `results.json` SHA를 검사하고 013번 source_scene/RGB만 읽었다.
- 같은 `region.trace_scene`으로 재추적해 기존 7개 connector의 전체 필드를 정확히 재현했다.
- GT/PPT/annotation/offline target을 읽지 않았다. 검출 bbox/owner ID/인식 문자열은
  고정된 이미지 단독 예측 결과다. 도착 문자열이 같은 cat이어도 독립 owner로 유지했다.
- 반환된 component label을 다시 만들고, 해당 component와 복구·팽창 전 `stroke_mask`
  원본 선택 픽셀의 교집합에 최소제곱 직선(TLS)을 맞췄다. `stroke_mask` 자체는 지역
  밝기/색 관측을 사용한 마스크이며, 완전히 전처리하지 않은 RGB를 뜻하지 않는다.
- 직선과 기존 예측 bbox의 교차만 계산했다. bbox를 움직이거나 GT 좌표로 고치지 않았다.

## 측정과 육안

아래 거리는 **원본 RGB 픽셀** 단위다. native gate는 1.2배 정규화한 좌표에서 적용된다.

| 관측량, 대각선 6개 | 범위 |
|---|---:|
| 원본 선 선택 픽셀→TLS 직선 수직거리 p95 | 1.403–1.445px |
| 원본 선 선택 픽셀→TLS 직선 최대 수직거리 | 1.480–1.521px |
| 현재 추적 정점→TLS 직선 최대 수직거리 | 2.742–2.914px |
| TLS 직선과 두 owner bbox 교차 | 6/6 모두 양쪽 교차 |
| 기존 끝점→교점 변위 | 0.476–4.199px |

기존 native fitting 탈락 오차는 정규화 좌표 **4.812–6.177px**다. 이는 위 수직거리와
다른 측도다. 기존 fitter는 고정 끝점을 잇는 line 또는 bentConnector3와 전체 추적
polyline 사이 양방향 최대 거리를 계산한다. 측도와 단위를 섞어 gate 통과를 추정하지 않는다.

그림 왼쪽의 빨간 추적선은 검은 선 가장자리 바깥으로 치우치며 끝에 작은 꺾임이 있다.
오른쪽 파란 TLS 선은 원본 선과 자연스럽게 정렬되고 같은 예측 owner 경계에 닿는다.
대조군 세로 ROOT–runs는 원본 잉크 수직거리 p95 약1px, trace 정점 잔차 약0이며
기존 writer도 이미 출력한다. 이 대조는 대각선 관측 경로의 문제를 좁히는 근거다.

## 코드 경계와 해석 한계

`tracing.py`는 owner 마스킹 후 수평/수직 closing과 3×3 dilation을 거쳐 연결 성분을
만든다. `shortest`는 8방향 한 걸음의 비용을 동일하게 두는 BFS이며 원본 선 중심을
추정하는 목적함수를 갖지 않는다. 이후 `approxPolyDP` 및 가장 가까운 bbox 경계 투영을
사용한다. 이 전체 경로가 직선 중심선과 달라지는 사실은 재현·그림으로 확인했다.
각 연산의 개별 기여도는 아직 ablation하지 않았으므로 dilation 또는 BFS 하나만의
영향량으로 분해해 주장하지 않는다.

TLS 선이 육안으로 좋아 보여도 범용 교정 알고리즘으로 검증된 것은 아니다. 엘보,
곡선, 교차선, 평행선, 분기, 글자에 닿은 선은 하나의 직선으로 바꾸면 안 된다.
방향 관측·누락된 연결 탐색·잘못된 owner는 이 적합으로 해결되지 않는다.
이 두 노드짜리 성분 진단을 실제 fanout에 그대로 적용하지 않는다.

## 병행 중복 진단의 확인

학습 작업의 `4a10afb`를 루트 `8472ab2`에 통합했다. 결합된 원본/코드 SHA와 세 중복
쌍의 IoU/작은 bbox 겹침/GT 최대 IoU를 루트에서 독립 재계산했다. 세 unmatched bbox의
GT IoU는 모두 .5 미만이다. 따라서 앞선 R8-A의 endpoint 실패를 **일대일 매칭 자리
경쟁만으로 설명하면 불충분**하다. 위치 정합성 실패가 함께 있다.

PP의 부정확한 bbox score .890이 정확한 bbox .524보다 높다. 낮은 NMS IoU 일괄 적용은
정확한 쪽을 삭제할 수 있다는 직접 반례다. 기존 점수·GT·문자열만으로 병합하지 않는다.
중복 owner 교정과 선 중심 관측 개선은 별도 개입으로 실험해야 한다.
