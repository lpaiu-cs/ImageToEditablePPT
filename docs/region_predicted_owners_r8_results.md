# R8-P 결과: 검출 향상과 native 결과의 간극

## 판정

**부분 개선이나 제품 승인 불가.** 고정된 ML 예측을 기존 R6 추적/OCR/native 단계에
연결했다. 정답 annotation은 변환 이후 별도 평가에서만 읽었다. 동일 개발 15장의
실제 PowerPoint 렌더를 원본과 나란히 전부 육안 확인했다. 객체 배치는 좋아졌지만
대각선 연결 누락, 그래프 오류, 트리 전부 공백이 남는다.

학습 트랙의 handoff 커밋 `8328219`를 본 브랜치에 `17a35ba`로 통합하고 최종 bundle을
독립 재검증했다. 과거 추론의 코드 실행 SHA 미확인과 legacy 클래스 추정이라는 한계는
유지한다. 신규 검출기 학습/재추론 결과가 아니라 기존 예측의 downstream 실험이다.

## 동일 집합 비교

각 칸은 TP / FP / FN이다. 최종 객체에 추가 detector NMS를 적용하지 않는다.

| 항목 | R8 morphology 기준선 | R8-P 고정 ML 예측 |
|---|---:|---:|
| node 역할+상자 | 63 / 5 / 28 | 91 / 3 / 0 |
| node 역할+상자+주석 종류 | 32 / 36 / 59 | 91 / 3 / 0 |
| container 역할+상자 | 4 / 3 / 7 | 11 / 0 / 0 |
| container 역할+상자+주석 종류 | 1 / 6 / 10 | 11 / 0 / 0 |
| 추적 방향 관계 | 22 / 8 / 45 | 35 / 16 / 32 |
| 최종 native 방향 관계 | 16 / 2 / 51 | 22 / 2 / 45 |

일치 node 라벨은 기존 63개 중 61개 정답·2개 공백, 이번에는 91개 중 62개 정답·29개
공백이다. 이번 일치 node에서 관측된 오문자는 0개지만 작은 문자를 대부분 생략한 결과다.
예측 전체 94개 node 중 라벨 62개이며, 공백 32개에는 불일치/중복 객체 3개도 포함된다.
트리의 text-only 객체 28개는 모두 라벨을 얻지 못해 최종 PPT에서도 보이지 않는다.
**객체 94개가 저장됐다는 것을 유용한 가시 객체 94개로 해석하면 안 된다.**

추적 연결 51개 중 27개가 출력에서 빠졌다. 14개는 text-only owner 부착 미지원,
13개는 기존 native preset의 4px 경로 적합 실패다. 합계로는 참 연결 13개와 오연결
14개가 함께 제거됐다. 따라서 최종 FP 감소만 보고 추적이 개선됐다고 판단할 수 없다.

## 육안 관측

- block flow: 중앙 세로 화살표는 올바른 아래 방향이다. 학습 트랙 v1의 provider에서
  나타난 반전과는 다른 경로다. 대각선 가지 다수는 빠지며 파란 분기 그림은 연결 전부
  사라졌다. 흐린 테두리는 검출 bbox에서 border 색을 추정하는 경계도 불안정함을 보여 준다.
- cycle: 이전의 거대한 가짜 타원/합쳐진 라벨 대신 개별 node와 두 container가 배치됐다.
  그러나 순환을 이루는 연결의 절반은 빠졌다.
- graph 두 장: 원형이 사각형으로 출력되고 일부 문자가 비며 교차 관계 대부분이 없다.
  최종 오연결 2개도 남는다. 정확한 구조 초안이라고 승인할 수 없다.
- layered stack 세 장: 이번에는 모두 5개 node와 4개 아래 방향 연결, 라벨을 유지한다.
  형태 추정보다 작은 글자 크기와 테두리 가시성이 다음 편집 품질 문제다.
- orthogonal flow: 3개 중 1개 연결 누락, 남은 경로도 일부 곧은 선으로 단순화된다.
- table matrix 두 장: 위치와 문자열은 유지하지만 일부 박스 테두리가 거의 보이지 않는다.
- tree 세 장: **완전한 빈 화면**. 모델이 위치를 찾은 사실은 출력 성공이 아니다.
  기존 OCR의 bbox 내부 3px 축소와 작은 글자 처리가 text-only 노드에 맞지 않는다.
  text-only owner에 연결하는 표현도 현재 writer에서 지원하지 않는다.

## 평가 target의 추가 한계

원형을 사각형으로 출력했는데도 graph의 종류 점수가 정답으로 잡힌다.
`graph_1302_00029`의 실제 주석 5개는 모두 `box`다. 생성 코드도 graph node의 의미 종류를
`BOX`로 두고 `SyntheticNodeStyle.shape`에서 별도로 `ellipse`를 선택한 뒤 PPT에는
OVAL을 쓴다. 따라서 **현재 exact-kind 점수는 주석 종류 일치이지 실제 렌더 기하 복원
정확도가 아니다.** 이 사실은 육안 결과에서 발견해 소스/주석으로 확인했다. 기존 동결
성적을 소급 수정하지 않으며 학습 트랙에 원본 PPT 기하와 target 계약 감사를 요청했다.
정답 PPT를 추론에 주입하는 방식으로 해결하지 않는다.

## 검증 및 보존

- 15개 별도 RGB-only subprocess, Python open allowlist 위반 0. OS 수준 격리는 아니다.
- 15개 PowerPoint native 렌더 성공. 객체/연결 ID, endpoint binding, PPT 및 렌더 SHA 확인.
  래스터 객체 0. 이 검증은 편집 구조의 형식 검증이지 인간 수정 시간 측정이 아니다.
- 통합 테스트 393개 통과, 기존 경고 9개. 새 테스트의 잘못된 enum 명칭을 고쳐 재실행했다.
  실험 runtime에는 그 테스트 오류가 사용되지 않았다.
- 기존 `region/*.py`, enum, 제품 CLI, 기존 baseline 산출물은 변경하지 않았다.
- 산출물: `artifacts/region-image-only-r8/predicted-owners-baseline/`.
  각 결과·소스·렌더 SHA는 추적 요약과 내부 manifest에 남긴다.

## 다음 실험 우선순위

1. 고정된 동일 예측에서 text-only OCR을 독립 개선한다. GT 문자열 복사나 언어적 추측은 금지한다.
2. text-only 객체의 편집 가능한 부착 표현을 별도 실험하고 OCR 변경과 출력 변경을 분리 비교한다.
3. owner 경계 근처의 관측과 경로 fitting 손실을 조사한다. 4px gate 완화만으로 성공 처리하지 않는다.
4. 학습 트랙은 원본 PPT의 의미 역할/실제 기하를 분리한 target 설계를 감사한다.

기존 오라클 연구나 이번 개발 집합으로 논문 이미지 일반화·제품 승인·시간 절감을 주장하지 않는다.
