# R12 원본 연결 성분 보완 경로

R11 고정 CLI와 그 결과는 유지한다. 새 경로의 질문은 연결 복구 morphology가 가까운 분기들을 합쳐 생긴 기권을 원본 ink로 줄일 수 있는가다. 알려진 reasoning 그림은 개발 사례이며 새 holdout이 아니다.

기존 owner/border mask까지는 같고, closing/dilation만 생략한 별도 trace를 만든다. 실제 원본 성분이 두 owner와 연결된 후보만 검사한다. 기존 B-v1 원본 중심선·연속성·제3 owner 충돌 검사를 그대로 통과한 후보만 보완한다. 방향은 기존 H 원본 화살촉 관측을 통과했을 때만 사용한다. 방향을 확인하지 못한 선은 화살표라고 추측하지 않는다. 기존 owner·텍스트·연결은 교체하지 않으며 이미 있는 owner 쌍과 중복하는 후보도 추가하지 않는다. 새 도형이나 가려진 새 경로는 만들지 않는다.

추론 입력은 RGB뿐이다. 기존 scene은 같은 실행에서 생성하며 이전 산출물/정답 annotation/PPT를 추론에 투입하지 않는다. OCR 캐시를 쓰는 진단은 fresh 실행과 구별한다. 결과를 본 뒤 B/H 기준을 낮추지 않는다.

검증: morphology로 합쳐지는 근접 분기 양성, 끊김·교차·곡선·제3 owner 음성, 기존 default 불변 테스트를 먼저 수행한다. 이어 알려진 복잡7개를 RGB부터 실행하고 실제 PowerPoint 렌더를 육안 대조한다. 도형·라벨 유지와 새 연결의 원본 근거를 개별 확인하며, 숫자 증가만으로 성공이라 부르지 않는다. 사진/기존 PPT 쌍 회귀도 통과하기 전 고정 CLI에는 채택하지 않는다.

## 원본 성분 진단 이후: component-local arm

첫 진단에서 morphology를 빼면 reasoning 후보 연결은18→24가 되지만, B-v1의 전역 seed 창에는 별개의 가까운 분기까지 들어와 신규 후보가 모두 탈락했다. 단순 raw trace 전체 채택은 하지 않는다. 후속 arm은 **관측한 두-owner 원본 연결 성분 전체**를 B-v1 `_fit` 입력으로 사용한다. 공간 corridor로 임의 절단하지 않으며 연결된 곁가지는 그대로 반례로 남는다. 밝은 배경, 기존 B-v1 수치 기준 및 모든 제3 owner 충돌 검사는 유지한다. 기존 H는 계속 전체 RGB로 관측하므로 방향 불확실은 LINE으로만 출력한다. raw trace의 폭 비교만으로 얻은 방향은 폐기한다.

이것은 B-v1 본체 변경이나 기존 결과 재판정이 아니라, 그 함수를 원본 성분 단위로 재사용하는 새 보완 경로다. 첫 진단의 신규3개 전부 탈락 사실과 후속 성분 단위 결과를 구분해 기록한다.
