# R15 구조 재현율 회복 설계 명세

상태: **설계 완료, 구현·실험 미실행**. 현재 사용자 요청은 육안 감사와 설계까지다. `closed-native-v4`를 덮어쓰거나 새 preset으로 승격하지 않는다.

## 1. 해결할 문제와 성공의 의미

R14는 오출력 방어를 개선했지만 original 핵심 노드8/17, 확인 연결4/20에 머문다. reasoning-full은 노드24/24여도 연결18/29다. 따라서 목표는 “남은 객체의 개별 편집 가능성”을 넘어 **사용자가 주요 흐름을 다시 그릴 필요가 없는 부분 구조**를 제공하는 것이다.

정밀도와 재현율을 단일 점수로 합쳐 서로 상쇄하지 않는다. 그림별로 노드/구획/제목/본문/연결/방향/분기/점선 스타일을 따로 평가한다. 불확실한 배경·아이콘을 생략한다는 원칙은 유지하지만, 이것을 확실한 구조의 누락을 면제하는 규칙으로 쓰지 않는다.

## 2. 핵심 설계 결정

### 2.1 구조 경계·내용·문자·연결의 판정을 분리한다

현재의 `content_audit.eligible` 하나가 내용의 texture와 도형의 존재를 동시에 결정하는 결합을 해소한다. 기존 audit dict에 필요한 근거만 추가하며 별도 프레임워크나 새 모델을 먼저 만들지 않는다.

| 판정 | 관측 근거 | 다른 판정에 미치는 범위 |
|---|---|---|
| 경계가 있는가 | 원본 변/곡선/닫힘·모서리·반복 관측 | geometry 후보를 생성, 곧바로 출력 승인하지 않음 |
| 구조 역할이 있는가 | 관측된 외부 연결, 계층, 반복 구조 및 신뢰 가능한 텍스트의 독립적 근거 | 아이콘/사진의 폐윤곽만으로 node 승격 금지 |
| 내부를 출력할 수 있는가 | picture/texture 영역, 내부 다른 owner, 대표 채움 | 내부 그림·fill 생략 여부; 외부 경계의 존재 증거를 지우지 않음 |
| 어떤 글자를 읽었는가 | 원본의 위치별 OCR 관측과 합의 | 해당 행/영역만 출력; 글자 실패가 경계를 지우지 않음 |
| 어떤 관계가 있는가 | 실제 shaft/분기점/arrowhead/port | 출발·도착·방향·경로·스타일을 독립 기록 |

분리한다고 해서 모든 닫힌 프레임을 살리지 않는다. standalone 사진 음성은 계속 음성이다. R14의 연결형 사진/아이콘 frame-only 승인 경계는 유지한다. 외부 연결 없는 사진 프레임이나 그 캡션까지 승인하는 정책 변경은 이 설계에 포함하지 않는다. 내부 그림이 없는 구조 노드의 신뢰 가능한 라벨은 함께 보존할 수 있으나, frame-only로 승인된 사진 카드의 캡션을 OCR 개선이라는 이름으로 부활시키지 않는다.

### 2.2 후보 생성과 최종 출력은 다르게 보수적이어야 한다

후보 단계의 과잉 제안은 최종 위양성과 다르다. 현재 Canny/dark threshold 합의·폐사각형 선택은 baseline으로 유지하고 별도 보완 arm을 둔다. 내부 texture/OCR 실패 후보도 경계 감사와 연결 추적의 obstacle/port 관측에 남긴다. **출력되지 않은 후보를 자동 node로 쓰지는 않는다.**

보완은 기존 선분·폐윤곽 helper를 먼저 재사용한다. 서로 만나는 실제 변과 모서리의 지지가 있는 사각/둥근 박스, 일치하는 양쪽 변이 텍스트 구간에서 끊긴 경우를 후보로 제안한다. bbox를 먼저 상상하고 가장 가까운 잉크에 끼워 맞추는 방식은 금지한다. 새 후보마다 어떤 원본 픽셀이 각 변과 가림 구간을 지지하는지 기록한다.

원통형 DB·연산 원·외곽 panel은 별도 family다. 지원하지 못해도 평가 분모에서 삭제하지 않는다. 닫힌 구조의 단순 editable 근사를 허용하되 DB 아이콘 자체를 구조로 세지 않는다. 이들 family를 사각형 cutoff 완화에 몰아넣지 않는다.

### 2.3 연결은 후보 owner 선택의 부산물이 아니라 관측 그래프다

source stroke를 실제 분기점과 terminal에서 분해해 원본 잉크 구간 그래프를 만든다. 기존 `source_centerline_v2`의 support/segment-box 검사와 `nested_owner_evidence`의 경계 마스크를 재사용한다. 단일 connected component를 하나의 source→target으로 해석하지 않는다.

- 실제 junction과 단순 교차를 구분한다. 끊김/넘김/접합의 픽셀 근거가 없으면 교차에서 새 연결을 만들지 않는다.
- shared trunk 뒤의 여러 terminal은 각각 별도 관계로 평가한다. “한 owner-pair 하나만 남음”으로 전체 fan-out을 대체하지 않는다.
- box 경계를 shaft로 타고 넘어가지 않도록 구조 경계와 외부 stroke를 구분한다. 가려진 방향의 연결은 명확한 collinearity·스타일 일치가 있어야 한다.
- 방향은 의미적 추측이나 출발 owner 순서가 아니라 원본 tip/shaft 근거에서 결정한다. 불명확하면 방향 없는 선 또는 기권을 명시하고 방향 TP로 세지 않는다.
- 점선은 dash 사이의 정렬·간격·방향 일관성과 양끝 근거를 확인한다. 임의의 빈 공간을 점선이라고 연결하지 않는다.

원본 r3:0의 노드 경계 합류, r3:1의 역방향, r3:7의 perimeter 우회가 필수 음성/수정 대조다. 잘못된 후보를 그냥 렌더링하는 접근은 즉시 실패다.

### 2.4 올바른 경로의 native 표현 실패만 별도로 해결한다

현재 `_path_fit.fit_path`는 line과 bentConnector3만 탐색한다. 먼저 RGB 근거로 승인한 경로에 대해서만 더 많은 native elbow 표현을 조사한다. bend 수와 위치가 실제 source path에 맞는지 검사하고, 가능한 한 한 관계를 한 native connector로 유지한다.

native bentConnector4/5 등은 실제 PowerPoint에서 attachment·저장/재열기·이동 동작을 확인한 뒤 사용할 수 있다. preset 지원을 코드상 이름만 보고 가정하지 않는다. 다중 조정값이나 custom geometry는 실측이 필요하다. 경로가 맞지 않는데 일직선으로 펴거나 여러 선을 그룹화한 뒤 같은 편집성이라고 보고하지 않는다.

기존4px fit cutoff의 좌표계는 normalize 후 좌표임을 명시한다. 원본1px와 혼용하지 않으며, 4.0795 사례를 통과시키려 cutoff를 사후 변경하지 않는다. 새 표현으로 오차를 줄일 수 있는지부터 확인한다. 결과가 실제 PowerPoint에서 연결을 잃으면 해당 arm을 채택하지 않는다.

### 2.5 OCR는 원본 행 단위 복원으로 다룬다

`owned_text_consensus`/`source_text_rows`를 재사용하되, 현재 stable-prefix에서 어떤 행이 잘렸는지 관측한다. 위치가 겹치지 않는 신뢰 가능한 뒤쪽 행을 앞줄 실패만으로 버려야 하는지 별도 arm으로 평가한다. 이름 사전, 원본 annotation, 문맥 추측으로 문자열을 채우지 않는다.

제목과 설명문을 별도 성능 항목으로 둔다. PyPDF처럼 제목 일부만 남으면 전체 텍스트 성공으로 세지 않는다. 반면 한 행의 공백·배치 오류는 노드 부재나 문단 전체 부재와 구별한다. 위치별 텍스트를 native owner 안에서 편집 가능하게 보존한다.

## 3. 실행 순서와 각 단계의 중단 조건

| 단계 | 변경 범위 | 먼저 답할 질문 | 중단/전환 조건 |
|---|---|---|---|
| R15.0 관측 고정 | 손실 장부·현재 산출물 SHA | 무엇이 실제로 없는가 | 이번 감사로 완료; 독립 GT로 승격하지 않음 |
| R15.1 경계 후보 회복 | 후보 생성 + 경계/내용 audit 분리 | original 후보 부재6개 중 관측 가능한 경계가 왜 누락됐나 | 후보가 늘어도 실제 구조가 늘지 않으면 채택 안 함 |
| R15.2 관계 추적 | 원본 stroke 구간·junction·tip·port | missing fan-out/fan-in과 경계 혼합을 고쳤나 | 잘못된 관계/방향 신규 발생 시 해당 arm 탈락 |
| R15.3 native 표현 | 승인된 path의 writer만 | 정확한 path를 editable connector로 유지하나 | owner 이동·재열기 후 attachment/경로 실패 시 탈락 |
| R15.4 내용 복원 | OCR 행·설명문, 제한된 채움 | 제목뿐 아니라 실제 수정해야 할 글이 줄었나 | 사진 캡션 부활, OCR 환각, 새 라벨 손실 시 탈락 |
| R15.5 통합 | 통과 arm만 조합 | 주요 흐름이 보존되고 수작업이 줄었나 | 아래 안전성·재현율·육안 gate 모두 필요 |

변경된 arm 외의 설정은 고정한다. baseline, 각 단일 arm, 통합 결과를 같은 RGB에 실행해 단계별 손실을 비교한다. 세부 cutoff가 필요한 경우 노출된 original에 맞춰 값을 고르지 않고 별도 calibration split에서 정한 뒤 eval 전에 lock한다. 값이 아직 정해지지 않은 helper는 실행 준비가 끝났다고 선언하지 않는다.

## 4. 정답쌍과 평가 경계

### 입력/정답 분리

학습·평가의 실제 정답은 **원본 PPT와 그 PPT의 렌더 RGB**다. 추론 프로세스는 복사된 RGB만 입력으로 받고 source PPT/XML/annotation/본 장부를 열지 않는다. 평가기가 추론 종료 후 별도 경로에서 source PPT의 객체·관계와 결과를 비교한다. 예측 PPT를 새 GT로 쓰지 않는다.

기존 `extract_offline_ppt_targets.py`와 pair provenance 도구를 재사용한다. source object 역할은 native/raster 저장 방식만으로 지정하지 않는다. 사진 카드 외곽·내부 그림·텍스트·구조 구획을 source 단계에서 구분해 라벨링한다.

과거336 train쌍은 레포의 `r10_picture_classifier_data_feasibility.md`에 provenance 한계와 사진 음성0개가 보고돼 있다. 이번에 그 payload를 다시 검증하지 않았으므로 현재 수치로 재확정하지 않는다. 새 실행 전 파일/SHA를 재검증하고, 실제 PPT→COM receipt가 필요하면 같은 source PPT를 새 디렉터리에 렌더한다. 과거 데이터의 렌더 연결을 소급 입증했다고 하지 않는다.

### 개발/검증 집합

- 이번7개는 이미 노출된 **진단·회귀 집합**이다. 새로운 일반화 성공을 주장하는 데 사용하지 않는다.
- 기존43개 안전성 대조를 그대로 회귀 검사한다. 사진2asset의 파생을 독립 자연사진 여러 개로 계산하지 않는다.
- 다음 실행 전 source PPT 구조 family별로 노드, parent, 분기/합류, 교차, 양방향, 점선, 캡션 사진, 무라벨 구조, 두꺼운 테두리 대조를 정한다. 구조 layout과 asset lineage로 calibration/eval을 분리한다. 같은 PPT 재렌더·crop은 같은 split이다.
- 기존 데이터에서 해당 family가 없으면 없다고 기록하고 제한된 source PPT 통제를 추가한다. 새로운 자연사진 자산·대규모 생성·학습은 현재 설계에 대한 실행 승인 없이 시작하지 않는다.
- Phase16 동결 holdout은 열지 않는다. 새 개발 eval은 그 holdout을 대체하거나 과거 공식 판정을 변경하지 않는다.

### 평가 항목

1. **후보 ceiling**: 실제 구조 중 후보 단계에서 포착한 비율. 최종 TP와 분리.
2. **node/container 재현율·정밀도**: one-to-one 대응. 동일 객체를 여러 조각으로 내보낸 경우 중복 TP 금지. 본 감사의 대략적 bbox는 정밀 scoring에 사용하지 않는다.
3. **관계 재현율·정밀도**: 원본 owner-pair·방향·분기별로 대응. shaft만 존재하면 방향 성공으로 세지 않는다. source path와 native path도 별도 비교.
4. **텍스트**: 제목/본문의 보존·누락·추가·철자·공백 오류. 라벨1개가 있다는 값으로 문단 전체 복원을 대표하지 않는다.
5. **경계 허용 오차**: 사전에 정한 source-pixel 기준으로 평가하며1px 경계 불확실성만으로 실패시키지 않는다. 객체 IoU와 실제 경계 편차를 함께 기록하고 미지원 shape를 평가에서 제거하지 않는다.
6. **실제 편집성**: PPT COM 렌더, 저장/재열기, 연결된 노드 이동, label 변경, child/panel 이동. 시각 PNG만으로 attachment 성공을 추정하지 않는다.
7. **남은 작업**: 다시 만들 노드/구획/관계와 다시 입력할 문단 목록. 실제 사람 측정 전에는 분·초나 시간 절감률로 환산하지 않는다.

## 5. 채택 gate — 제안 기준, 사용자 승인 기준으로 사칭하지 않음

현재 사용자는 기준 미달이라고 판정했지만 숫자 기준을 지정하지 않았다. 아래는 다음 실험에 제안하는 공학적 gate다. 실행 전에 확정해 lock하며 결과를 보고 낮추지 않는다.

- **안전성 필수**: 기존 안전성43개에서 새 비구조 출력/사진 캡션 누출/잘못된 owner 연결·방향0건. 정상 사례의 유용한 기존 node/label/edge가 새로 사라지면 회귀로 탈락. 새 eval의 각 failure도 공개한다. 단순 총정밀도 개선으로 개별 신규 위양성을 숨기지 않는다.
- **재현율 목표**: 점수를 확정할 수 있는 각 구조 family에서 node/container80% 이상, 방향 관계75% 이상. macro와 각 그림/각 family를 같이 공개하고 empty-edge 사례는 N/A로 둔다. original의 경우 최소14/17노드와 장부의15/20관계가 필요하다는 개발 목표이지 production 승인 조건 전부가 아니다.
- **흐름 필수**: original의 검색·생성·ACT 분기처럼 감사에서 지정한 핵심 왕복/분기와 reasoning-full의 분기·합류가 실제 출력에서 추적 가능해야 한다. 나머지 쉬운 객체만 늘려 평균을 통과할 수 없다. 불확실한 경로를 발명해 이 gate를 맞추지 않는다.
- **텍스트 필수**: 기존 정확한 제목 손실0, 제목/본문 누락을 따로 줄였다는 source 비교가 필요하다. frame-only의 정책상 빈 글자는 별도 계수한다.
- **실제 PPT 필수**: 새로 복구한 관계의 실제 COM 및 편집 probe 통과. 시각 비교는 원본과 전체 렌더, 실패부 확대를 모두 본다.
- **최종 판정**: 기계 점수 통과 뒤에도 주요 흐름을 다시 그려야 하면 기준 미달이다. production 승인 및 실제 사용자 시간 절감은 별도 사용자 확인/사람 평가가 필요하다.

## 6. 구현 범위와 제외

우선 수정 후보는 `research/closed_rect_proposals.py`, `closed_content_gate.py`, `nested_owner_evidence.py`, `source_centerline_v2.py`, `owned_text_consensus.py`, 그리고 마지막 단계의 `region/_path_fit.py`/`emitter.py`다. 기존 `run_closed_rect_proposal_probe.py`에 독립 arm과 단계별 누락 기록을 연결한다. 새 서비스·패키지·범용 플러그인·학습 모델은 지금 만들지 않는다.

의미 분류가 기존 근거만으로 안전하게 분리되지 않는 경우, cutoff 예외를 계속 추가하지 않고 그 family를 미해결로 남긴다. 이후 실제 GT쌍으로 학습하는 별도 설계가 필요할 수 있지만 현재의 사진2개로 새 일반 분류기를 학습하는 계획은 채택하지 않는다.

이번 인계물은 **손실의 실제 크기, 잘못된 원인 설명의 정정, 다음 실험의 입력·단계·평가·중단 조건**이다. 복원 성능 개선을 이미 달성했다는 보고가 아니다.
