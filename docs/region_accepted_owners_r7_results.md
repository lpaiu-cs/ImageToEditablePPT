# R7 / R7b 결과: 분류기보다 소유 객체 표현의 경계가 먼저다

## 판정

**일반화·프로덕션 승격 보류.** 정답 역할을 공급해도 현재 표현과 추적기는 복잡 도식의
전체 핵심 구조를 복원하지 못한다. 따라서 당장 역할 분류기를 학습하는 순서는 채택하지 않는다.
다만, 미출력 객체도 경로 차단 영역으로 유지하고 채움색을 객체 소유 영역에서만 읽는
변경은 이번 개발 사례에서 분리 가능한 개선을 보였다. 이 부분을 후속 표현 설계의 근거로 남긴다.

R6 `0b9c699`에서 `codex/accepted-owners-r7`로 분기했다. 기존 R6 런타임/CLI의
바이트 해시는 그대로이며, 승인된 v0.3 및 Phase16 동결 자료는 변경하지 않았다.
새 보고서·설계 명세의 한글 작성 규칙은 `AGENTS.md`에 반영했다.

## 실제 수행

1. 원본을 직접 보고 새 원본 픽셀 주석 4개를 작성했다. 원본 SHA·크기·부분 영역·표시 변환을
   검증하고 주석 오버레이를 육안으로 다시 확인한 뒤 입력/구현 해시를 동결했다.
2. 후보 장면과 승인 장면을 별도 타입으로 나누고, 연구용 OCR/추적은 승인 장면만 받게 했다.
   자동 CLI는 이 경로를 가져오지 않는다. 정답 라벨과 연결 목록은 인식에 주입하지 않았다.
3. 전역 후보, 고정 타일 후보, 역할/형태 정답 승인, 정확한 상자 직접 공급을 비교했다.
   역할 오라클은 부모와 native 도형 종류도 정답으로 공급한다. 순수 역할 분류기 성능이 아니다.
4. R7의 실제 PowerPoint 렌더 16개와 원본 위 추적 경로를 검토했다.
5. 관측한 원인에 따라 별도 R7b 명세/해시를 동결하고 차단 영역·경계 성분 보류·소유 채움을
   구현했다. R7의 코드나 결과를 수정하지 않고 최종 PPT 4개를 추가 렌더했다.

두 단계 모두 이미 본 개발 자료를 사용했다. p058은 LLM 패널 부분, P159는 오른쪽
연산 노드 부분만 평가했다. 새 출처의 일반화 표본, 독립 주석 감사, 보정/승인 집합은 없다.
R7b는 R7 결과를 본 뒤 수행한 후속 개발 실험이며 동일 실험의 사후 구제가 아니다.

## R7: 후보를 더 만드는 것만으로는 해결되지 않았다

| 개발 영역 | 전역 후보 → 지역 후보 | 매칭 객체 / 전체 정답 | 결과 |
|---|---:|---:|---|
| p058 LLM 패널 | 6 → 6 | 6/6 | 좁힌 영역에서는 R6도 이미 부모 3·노드 3을 찾음 |
| P084 원통 흐름 | 11 → 12 | 3/7 | 원통 4개는 여전히 누락, 타일은 비구조 후보만 추가 |
| P159 오른쪽 연산 | 8 → 8 | 8/8 | 사각형 연산 노드는 이미 회수됨 |
| P009 사진/차트 | 3 → 5 | 정답 객체 없음 | 사진 유래 거짓 후보가 증가 |

전체 21개 중 17개를 매칭했다. 현행 지원 도형 17개만 보면 이미 17/17이므로,
이 집합은 작은 노드 회수율 향상을 입증하는 데 충분하지 않다. 지역 타일의 일반적
효용을 부정할 수는 없지만, 이번 결과에는 추가 TP 없이 거짓/미매칭 후보 3개만 늘었다.
사진 후보를 정답 역할로 모두 거부한 결과는 오라클 효과이며 자동 배제 성능 증거가 아니다.

## R7: 추적 정확도와 native 표현 가능성을 혼동하면 안 된다

| 정답 역할 승인 장면 | 추적 TP | 추적 FP | 최종 PPT TP | 최종 PPT FP |
|---|---:|---:|---:|---:|
| P084 | 1 | 2 | 1 | 0 |
| P159 부분 영역 | 5 | 1 | 5 | 0 |

정확한 원본 상자를 직접 공급해도 같은 FP가 남았다. 기존 preset 적합성 검사가
잘못된 경로를 모두 거부했기 때문에 최종 PPT만 보면 문제가 가려진다. 향후 곡선/U자
표현을 더 지원하면서 이 경로들을 그대로 살리면 오히려 거짓 연결이 노출될 수 있다.

### 육안으로 확인한 원인

- **P084:** 출력하지 못한 원통이 마스킹 대상에서도 빠졌다. 추적기가 원통의 옆면을
  연결선처럼 따라가면서 `annotation → model`, `model → batch`라는 잘못된
  지름길을 만들었다. 원본은 각각 중간 원통 객체를 거치는 별도 관계다.
- **P159:** 부분 영역 밖에서 올라오는 공유 입력을 `residual → conv-lower`로 해석했다.
  입력의 분기와 실제 출발 노드를 표현하지 않고, 성분에서 만난 두 객체만 짝지은 결과다.
- **p058:** 부모 내부의 자식 색이 채움 표본에 섞였다. 옅은 회색 노드도 투명하게
  출력되어 부모의 노란색이 비쳤다. 부모/자식 ID가 맞아도 스타일 샘플링의 소유 관계는 틀렸다.
- **P084 모델 상자:** 내부 신경망 삽화의 색이 회색 채움으로 남았다. 아이콘을 native
  객체로 출력하지 않는 것만으로는 비구조 정보가 결과에 남는 문제를 막을 수 없다.

## R7b: 원인별 차단 실험

동일 후보·역할·상자·OCR 문자열을 유지한 채 단계별 효과를 분리했다.

| 영역 | R7 추적 FP | 미지원 객체 차단 후 | 외부 경계 성분 보류 후 | 보존된 TP |
|---|---:|---:|---:|---:|
| P084 | 2 | 0 | 0 | 1 |
| P159 부분 영역 | 1 | 1 | 0 | 5 |
| p058 / P009 | 0 | 0 | 0 | 관계 정답 없음 |

단순하고 올바른 직접 연결 6개를 잃지 않고 이번 집합의 추적 FP 3개를 제거했다.
최종 PPT의 관계 수는 R7과 동일하다. **출력 관계를 늘린 성과가 아니라, 추적 자체의
오류를 출력 단계의 우연한 거부에 의존하지 않도록 제거한 성과**다.

원통 4개와 관련 관계는 여전히 복구하지 않는다. P084의 실제 관계 7개 중 1개만
남으며, P159에서 평가한 것은 직접 연결 5개뿐이다. 잔차 전체 그래프의 성공이 아니다.
경계 접촉 보류는 진짜 관계도 버릴 수 있다. 이번 직접 연결에서는 손실이 없었으나
다른 부분 영역 배치에서의 회수율 비용은 아직 측정하지 않았다.

## 실제 렌더의 육안 판정

- p058: 부모 분홍색 `(248,206,204)`, 자식 패널 노란색 `(255,242,204)`, 내부 노드
  회색 `(245,245,245)`이 분리되어 이전의 색 섞임과 투명 비침이 사라졌다. 부모·자식
  경계도 읽을 수 있다. **이 개선은 육안으로 확인했다.** 다만 제목 3개는 이번 OCR 대상이
  아니고 GPT 4.0 라벨은 여전히 비어 있어, 전체 결과를 승인 가능한 품질로 판정하지 않는다.
- P084: 내부 삽화에서 나온 회색 채움이 사라지고 흰색 구조 상자만 남았다. 그러나 원통과
  주요 흐름이 대부분 비어 있어 완성도는 낮다. 모델 라벨도 비어 있다.
- P159: 직접 사슬 5개는 유지되지만 Linear Layer 라벨은 비어 있고, 위쪽 WeightNorm
  라벨에는 `R`이 중복된다. 이 OCR 오류는 R7b에서 변경하지 않았다.
- P009: 비대상 그림은 전부 공백이다. 정답 제외 마스크를 공급한 실험이므로 자동 일반화
  성과로 계산하지 않는다.

최종 R7b의 지원 노드 14개 중 라벨은 공백·대소문자 정규화 후 10개 일치, 1개 오류,
3개 공백이다. 완전한 문자열/줄바꿈/글꼴 일치 지표가 아니다. 컨테이너 제목은 제외했다.

## 검증과 증거

- 전체 테스트: **341 passed, 기존 경고 9개**. 신규 R7/R7b 테스트 32개.
- 실제 PowerPoint로 R7 16개·R7b 4개 PPT를 열어 렌더했다.
- 20개 PPT의 native ID·연결 소유자 바인딩·래스터 객체 0개를 확인했다.
- R7b는 의도한 채움값뿐 아니라 실제 PPT 객체의 색값도 검증했다.
- R7/R7b 동결 해시, 원본/주석/결과/렌더 해시를 검증했다. 기존 R6 런타임/CLI 변경 없음.
- 새 wheel, 배포, 자동 역할 모델, 실제 사람의 편집 시간 측정은 수행하지 않았다.
- 기존 v0.3의 이동/크기 변경/재열기 실험을 새로 수행한 것으로 주장하지 않는다.

## 다음 설계 결정

1. **출력 가능성과 존재 여부를 분리한다.** 지원/미지원/불확실 객체를 모두 관측 장면에
   보존하되, 확실한 지원 객체만 native 출력한다. 미출력 객체는 연결선의 우회 통로가 아니다.
2. **연결을 두 객체의 짝이 아닌 관측 선 조각과 포트로 표현한다.** 외부 입력 단자,
   화살촉, 분기, 불확실 교차점과 닫힌 객체 테두리를 구별한 뒤 소유 관계를 해석한다.
3. **원통을 복합 폐곡선 객체로 지원한다.** 윗면 타원과 몸통이 같은 객체라는 기하 근거,
   실제 접점, native 편집성을 별도로 검증한다. 이 작업 전 곡선 preset만 확장하지 않는다.
4. **채움·OCR에도 같은 소유 관계를 적용한다.** 이번 소유 영역 채움은 유효한 출발점이다.
   제목 영역과 노드 내부 라벨을 분리해야 하며, 정답 텍스트를 복사하는 방식은 금지한다.
5. 위 표현 단계의 오라클 한계가 개선된 뒤 새 출처 그룹의 개발/보정/승인 데이터를
   확보하고 역할 분류기를 검토한다. R6/R7 자료를 미관측 승인 집합으로 재사용하지 않는다.

이번 결론은 “모델만 더 잘 학습하면 된다”가 아니다. **관측한 객체를 잊지 않고,
출력·추적·채움이 같은 소유 관계를 사용하도록 만드는 것이 먼저**다.
