# R10-P2: 닫힌 박스의 소유 영역과 원본 라벨 위치

## 수정 근거

복잡 6개를 실제 PowerPoint로 렌더링해 원본과 비교했다. P1은 중첩 패널의 자식 글자를 부모 라벨에 재사용했고, 부모의 중앙값 색이 자식 채움에 오염됐다. 부모 제목까지 중앙 정렬하여 실제 자식과 겹쳤다. 이는 픽셀 오차가 아니라 소유 관계 오류이다.

## 계약

- P1 제안 경계는 변경하지 않는다. RGB Canny의 별도 폐윤곽을 소유 영역 제외에 사용한다. 제외 윤곽이 곧 출력 객체라는 뜻은 아니다.
- 실제 내부 폐윤곽은 자식이 제안기 크기/종횡비 조건에서 탈락하더라도 부모의 글자와 채움을 제공할 수 없다. 충분한 크기와 사각 점유율을 가진 폐윤곽만 제외하고 글자 구멍까지 제거하지 않는다.
- OCR에는 원본 crop을 그대로 전달한다. 세 배율 OCR의 word bbox가 자식 제외 영역과 겹치면 그 단어는 부모 소유가 아니다. 남은 부모 단어에서 기존 완전한 연속 줄 일치 계약을 적용한다.
- 부모 라벨은 실제 OCR bbox로 계산한 native shape text-frame inset에 배치한다. 새 래스터나 별도 annotation은 넣지 않는다. 라벨이 도형과 함께 움직이는 편집성은 유지한다.
- 닫힌 내부에서 추정한 흰색은 흰색 채움이다. 투명하게 만들면 부모 색이 자식 내부에 비쳐 원본 소유 영역과 달라진다.
- 사진 프레임이나 glyph 구멍이 실제 사각형인 것과 구조적 diagram node인 것은 별개다. P2는 의미 분류기를 해결했다고 주장하지 않으며, P1 독립 반례와 누락은 그대로 남긴다.

## 검증 경계

독립 24개 소유 영역 fixture와 source-only 실행으로 부모/자식 라벨·색을 확인한다. 기존 P1 결과를 덮어쓰지 않는다. 원본과 복잡6개는 이미 노출된 개발 자료이며 holdout 또는 프로덕션 승인으로 부르지 않는다.

## 명시적 안쪽 경계 선택 실험

`--inner-boundaries`에서는 IoU .85 이상인 인접 경계가 모두 자신을 포함할 때 실제 안쪽 폐윤곽 하나를 남긴다. 여러 테두리를 하나로 합치는 것이 아니다. 그림자/테두리인지 추측하여 바깥쪽을 재구성하지 않고, 겹침 관계가 포함 관계가 아니면 기권한다. 진짜 중첩 사각형에서도 안쪽 하나만 남을 수 있으므로 P1의 `not_single` 완전성 계약을 통과했다고 주장하지 않는다. P1 기본 함수 결과와 동결 실패는 유지한다. 이 옵션의 목표는 존재하지 않는 경계를 만들지 않으면서 실제 편집 가능한 최소 사각형의 누락을 줄이는 것이다.

비교 대상도 두 threshold에서 안정적으로 확인된 경계로 한정한다. 약한 gradient의 한 threshold 전용 경계 때문에 두 threshold에 모두 존재하는 실제 테두리까지 누락시키지 않는다. 경계 자체의 닫힘·두 threshold 일치 기준은 완화하지 않는다.

독립 소유 영역 검사에서 얇은 자식 4개가 최소높이 때문에 제외되지 않았다. 기존 결과를 보존하고, 긴 얇은 폐사각(짧은 변≥6s, 긴 변≥40s)도 **소유 제외만** 허용하는 통제를 추가한다. 새 출력 노드를 추가하는 조건은 아니다. 열린 자식의 미검출 진단은 별개로 남긴다.

원인 정정: 위 얇은 자식4개 중 실제 raw 폐윤곽이 있는2개만 크기 필터 반례이다. 나머지2개는 raw 폐윤곽이 없으므로 크기 수정만으로 해결됐다고 주장하지 않는다.

파란 흐름도의 `(Section 3 3.4)`는 OCR 세 배율이 동일하게 틀린 사례이다. `Section 3`과 `3.4` 인식 창이 같은 숫자 픽셀을 겹쳐 읽었다. 수평 겹침이 max(2px,짧은창폭의10%)보다 큰 단어 창을 이어 붙인 줄은 기권한다. 문자열을 정답을 보고 교체하거나 반복 글자를 추측 삭제하지 않는다. 이때 앞서 확실했던 제목은 보존한다.

원본 QueryPlanner에서 OCR 세 줄의 bbox가 세로로 겹쳤다. bbox 높이를 단순 합산해 줄 간격으로 쓰면 원본 내부 라벨이 PPT 경계 밖으로 밀린다. 다음 줄의 관측 y 시작점까지의 간격을 사용하고 Arial 실제 폰트 폭으로 가로 맞춤을 제한한다. Arial 파일 SHA도 실행 lock에 넣는다. 도형/라벨 텍스트 자체와 연결은 바꾸지 않는다.

## 줄 전체 직접 읽기 실험

`--whole-lines`는 관측된 줄 영역을 원본에서 통째로 다시 읽는다. detector의 겹친 조각 문자열을 이어 붙이거나 반복 글자를 추측 삭제하지 않는다. 각 배율에서 얻은 실제 줄 bbox를 원본으로 환산해2px 여백 crop한 뒤1/1.5/2.25배 recognition-only 관측을 각각 수행한다. 세 관측의 완전한 문자열과 공간 위치가 모두 일치하고 신뢰도≥.98일 때만 유지한다. 자식 제외 영역을 침범하는 줄은 읽지 않는다. 앞의 불확실한 줄을 건너뛰어 뒷조각을 이어 붙이지 않는다. 이전 fragment 관측 기록도 감사용으로 보존한다.

전체 줄에 recognition-only를 강제 적용한 개발 실험은 원래 정상적으로 읽히던 제목까지 불필요하게 기권했다(`complex-whole-line/blue-flow` 보존). 채택 후보에서는 이 어댑터를 **OCR 창이 실제로 겹친 줄에만** 적용한다. 원래 겹침이 없던 줄은 기존3관측/.95 계약 그대로다. 새 recognition-only의.98 기준을 낮추지 않으며 두 결과 중 더 유리한 문자열을 고르는 방식은 사용하지 않는다.

## 원본 잉크 행 분리 대조

`--source-rows`는 OCR 검출 창 자체가 제목 앞부분을 놓치는 원인을 따로 점검한다. 닫힌 owner의 실제 소유 mask를 침식한 내부에서 대표색과64 이상 다른 잉크의 행을 추출한다. row당 max(2px,owner폭1%) 이상의 잉크가 있어야 하며1빈행까지만 같은 줄로 묶는다. 너무 작거나 owner높이 절반보다 큰 밴드는 텍스트 행으로 승인하지 않는다. 실제 잉크 bbox의 원본 crop을3배율에서 recognition-only로 읽고.98 이상 완전일치한 앞쪽 줄만 남긴다. 다른 OCR 경로의 유리한 결과와 합치지 않는 독립 대조이다. 아이콘과 글자가 같은 행에 있거나 실제 자식 경계가 열렸으면 이 경로도 기권/오인할 수 있으므로 별도 시각 검증이 필요하다.

작은 앞쪽 밴드를 단순 삭제하면 수식 위의 hat/accent가 사라진 평문 글자를 승인할 수 있다. 해당 밴드는 비텍스트/불확실 기록으로 남겨 prefix를 중단한다. 잡음인지 수식인지 확실하지 않은 상황에서 임의 삭제하지 않는다. 독립 글자72개에서는3배율 동일 문자 오답도 관측됐으므로.98을.95/.90으로 낮추는 안은 채택하지 않는다.

## 어두운 원본 테두리 대조

`--dark-boundaries`는 Canny 이중 에지 대신 실제 grayscale<130/<170의 어두운 픽셀 두 mask에서 폐hole을 제안한다. 두 threshold 모두 닫힘/사각 점유율/크기/경계 일치 조건을 통과해야 하며 closing이나 새 선 생성은 없다. reasoning의 분명한 검정 테두리 박스가 Canny에서는 빠지는 앞단 현상을 검증하는 독립 경로다. Canny 결과와 유리한 후보만 혼합하지 않는다. 사진 프레임의 의미 한계는 이 경로로 해결되지 않는다.

`--portrait-boxes`는 같은 최소 긴변32s/짧은변16s 및 종횡비1.15~15 조건을 세로 방향에도 대칭 적용한다. 정사각형·비정형 윤곽이나 열린 경계를 승인하는 조건은 아니다. 세로 박스의 글자 방향을 추측해 돌리지 않으며 기존 OCR가 불확실하면 라벨은 공백이다. 구조만 확실하게 편집 가능하도록 하는 별도 범위 확장이다.

## 개별 검증 폐윤곽의 합집합

두 단독 실행을 비교하면 dark는 reasoning24개를 찾지만 원본 input은0개이고, Canny는 원본10개를 찾는다. 고정 threshold의 밝기/색 범위 차이이므로 한 경로가 다른 경로의 일반적인 대체물이 아니다.

`--boundary-union`은 각 경로에서 이미 **자기 두 threshold의 닫힘 조건을 통과한** 실제 윤곽만 합친다. 면적이 작은 실재 윤곽부터 남기고 IoU .85 이상의 중복은 제거한다. bbox를 평균하거나 여러 조각으로 새 폐곡선을 만들지 않는다. 같은 그림에서 성능을 본 뒤 알고리즘을 고르는 per-image oracle이 아니라 모든 입력에 같은 두 절차를 적용하는 새 고정 실행이다. 각 후보의 method와 제외 기록을 저장하며 이전 단독 결과는 유지한다. geometry 합집합이므로 사진/아이콘의 의미 판별 한계는 그대로이며 별도 일반화 승인 주장을 하지 않는다.

## 고정 텍스트 통합 대조

`--owned-text`는 매 owner마다 같은 두 원본 관측을 모두 실행한다. 겹치는 OCR창의 whole-line 어댑터와 raw ink-row의 각 threshold는 그대로다. 둘 다 라벨을 승인했으나 문자열이 다르면 공백이다. 공통된 완전한 앞쪽 줄이 정확히 일치할 때만 더 긴 완전 prefix를 유지한다. 한쪽만 승인했다면 그쪽의 기존 독립 계약을 통과한 결과를 유지하되, 단일 글자는 다른 경로의 동의를 요구한다. 정답 문자열과 비교해 고르거나 confidence를 결과에 맞춰 낮추지 않는다. 양쪽 모두 동일하게 오인할 가능성은 남으므로 입력/실행/소유/최종 native 시각 검증을 별도로 유지한다.

작은 색 배지의 글자도 그 배지 소유이다. nested-panels의 PDF 아이콘 내부 빨간 배지(실제49×21px 폐윤곽)를 크기 때문에 제외하지 못해 `PDF/PDF`가 됐다. 소유 제외에 한해 짧은변≥4s/긴변≥12s이며 닫힌 내부 색의max-min≥40인 작은 색 배지를 포함한다. 회색/흰색 글자 구멍은 이 작은 크기 예외에 포함하지 않는다. 아이콘 자체를 새 도형으로 출력하지 않는다.

v1 실제 렌더에서 Sensory/Generation의 설명문이 불완전한 여는 괄호로 끝났다. 후속 통합 라벨은 괄호`()[]{}`가 닫힌 마지막 완전한 줄까지만 출력한다. 빠진 뒷문장을 추측하거나 괄호를 새로 붙이지 않는다. 원래 읽힌 조각은 `observed_accepted`에 남겨 텍스처 계산에서 실제 글자를 사진으로 오인하지 않도록 하고, 내보내지 않은 줄은 `withheld_incomplete_lines`로 구별한다. `<EOS>` 같은 token 표기는 이 괄호 규칙으로 바꾸지 않는다.
