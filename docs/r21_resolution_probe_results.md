# R21 결과: 전체 검출 해상도 증가는 복원을 개선하지 못함

2026-09-09. 사전등록 및 실행 코드 `e563a9a`. R19 checkpoint를 그대로 사용해 RPN/회귀를 포함한 전체 검출을 세 해상도로 실행했다. 임계값 .95, NMS .5, 최대 검출 100을 바꾸지 않았다. **실제 COM 육안 확인 결과 모두 기준 미달이며 제품 기본값에 반영하지 않는다.**

| min/max 입력 크기 | 후보 수 | 종류+위치 TP/FP/FN | 최종 위치 TP/FP/FN | 후보 위치 TP/FP/FN |
|---|---:|---|---|---|
| 600/960 | 94 | 1/8/16 | 5/4/12 | 14/80/3 |
| 1200/1920 | 100 | 2/6/15 | 3/5/14 | 13/87/4 |
| 1800/2880 | 100 | 1/11/16 | 1/11/16 | 7/93/10 |

17개 주요 노드의 이미 노출된 수동 장부를 **추론 후** 사용한 개발 진단이다. manual FP는 장부에 대응하지 않는 출력 수이지, 원본 전체 구조에 대한 완전한 라벨이 아니다. 600 조건은 R19 원본의 전체 후보와 최종 출력에 정확히 일치했다.

3개 PPT, 총29개 native 객체를 실제 PowerPoint COM1380×752로 렌더했다. 비교 보드와 1200/1800 개별 렌더를 직접 확인했다. 1200은 대부분 주요 노드를 여전히 빠뜨리고 잘못된 큰 사각형을 남긴다. 1800은 작은 파편·장식 부위에 가까운 객체가 늘면서 주요 노드 복원이 더 나빠진다. 1픽셀의 허용 오차 문제가 아니다. [실제 COM 비교](../artifacts/region-image-only-r21/audit-v1/comparison.png).

R20에서 **고정 bbox의 분류**는 해상도 증가로 개선됐지만, 이는 전체 파이프라인 개선을 뜻하지 않았다. R21은 후보 생성과 회귀가 함께 바뀌며 후보 위치 recall도 감소했다. 큰 두 조건이 출력 상한100에 도달했으나 저장된 post-NMS 후보만으로 상한, anchor scale, ranking 중 무엇이 주원인인지 확정할 수 없다. 상한을 사후 조정해 이번 결과를 구제하지 않는다. 원본 대조가 실패했으므로 선택 항목이었던 노출 R19 eval48 전체 해상도 대조는 생략했다.

다음은 R22 native 외형 다양화다. 좁은 합성 외형과 복잡한 원본 사이의 차이를 학습 데이터 개입으로 검사한다. geometry/종류/학습량을 고정한 외형 쌍을 쓰며, 이미 노출된 geometry 쌍을 새로운 독립 평가라고 부르지 않는다. 닫힌 구조만의 실험으로 전체 목표가 완료된 것은 아니며 사람의 수정 시간 측정도 아직 없다.
