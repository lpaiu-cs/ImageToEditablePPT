## 판정

**v1 실패. 실제 15장/PPT 대조에 진입하지 않는다.**
명세는 `c3fbbd9`, 수치 명확화와 구현/fixture는 첫 실행 전 `2188a91`에 커밋했다.
24개 clean positive, 10개 negative, 별도 선분 helper 1개를 실행했다.
결과는 **29 passed / 6 failed**다. positive 18개 통과·6개 실패, negative 10개는 모두
기권했고 helper 1개도 통과했다. 아직 wrapper의 범위 밖 불변 gate까지 완료한 것이 아니다.

실패 테스트를 고치거나 xfail로 숨기지 않았다. 현재 연구 브랜치의 해당 테스트는
6개가 실패하는 상태이며, 기존 R8의 458개 통과 기록과 합쳐 새 전체 통과로 보고하지 않는다.
R8 브랜치와 제품 코드는 그대로다. 이 실패는 fixture/픽셀 계약의 문제이며 아직 실행하지
않은 실제 이미지 성능 퇴행을 측정한 결과가 아니다.

## 실패 1: subpixel bin을 pixel-center 점유율로 계산

scale .75의 수평·수직 선, 각각 순방향/역방향 4개가 `discontinuous_source_support`로
기권했다. 원본에는 끊김 없는 선이 있지만 bin 폭이 .75px이고 관측은 정수 픽셀 중심
좌표이므로 일부 bin에 중심점이 들어가지 않는다.

- 실제 점유율: **.7552447552**, 연속 빈 bin 최대1.
- 수직거리 p95/max는 각1px로 직선성 조건은 통과한다.
- 기준 .90 때문에 실제 단절이 없는 선을 단절로 분류한다.

이는 원본 픽셀의 면적 지지와 중심점 표본의 점유율을 혼동한 관측 정의 문제다.
노이즈 제거 임계값이나 native 4px gate 문제가 아니다. v1에서 .90을 낮추지 않았다.

## 실패 2: 래스터화된 입력과 연속 선 기대값의 불일치

scale1.5의 반대 대각선에서 순방향/역방향 2개가 endpoint 기대값 검사에 실패했다.
fixture의 OpenCV 입력 좌표는 `np.rint`로 정수화한다. 35×1.5=52.5와
175×1.5=262.5가 각각52와262가 되어 관측 중심선은 x+y=314가 된다.
그러나 기대 endpoint는 정수화 전 x+y=315의 연속 기하를 사용한다.

관측 결과는 `(44,270)`, `(270,44)`로, 기대 `(45,270)`, `(270,45)`와1px 다르다.
기존 tolerance .8px에서 실패한다. 관측 직선성·연속성 조건은 통과했다.
이 두 실패를 중심선 알고리즘이 실제 source와 다르게 복원한 증거로 확대하지 않는다.
**fixture 기대값의 좌표 계약도 검증 대상**이며, v1 기대값을 사후 변경해 통과시키지 않는다.

## 다음 버전에서 먼저 고쳐야 할 계약

1. 원본 픽셀은 면적이 있는 cell이라는 점과 물리적 샘플링 해상도를 명시한다.
   선 지지 연속성을 정규화 단위의 빈 중심점 bin으로 판정하지 않는다.
2. fixture는 실제 생성된 래스터 선의 좌표/양자화와 별도 기대값을 결합한다.
   알고리즘의 출력으로 기대값을 만드는 순환 검증도 피한다.
3. 이 두 계약을 별도 v2로 사전 고정한 뒤 기존 실패·단절·평행선·곡선 반례를 모두 유지한다.
   v1 성적을 소급 바꾸지 않는다.
4. wrapper의 고정 owner/방향 및 범위 밖 불변을 확인한 뒤에만 실제15장 대조를 논의한다.

R9-D 중복 owner 관측은 다른 작업에서 독립적으로 G0~G2를 수행 중이다.
R9-C 실패를 이유로 D 기준을 완화하거나 두 결과를 섞지 않는다. 신규 학습·제품 승격·
GT 추론·실제 PPT 대조는 이번 작업에서 수행하지 않았다.
