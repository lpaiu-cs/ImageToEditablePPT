# R8-T 결과: 작은 문자 인식 개선, 출력 채택은 보류

## 판정

**OCR 전처리의 효과는 확인했으나 현재 후보는 제품 경로에 채택하지 않는다.**
고정된 R8-P의 text-only 객체 28개에만 사전 등록한 한 가지 crop 변환을 적용했다.
원본 PPT·annotation·새 offline target을 변환 입력으로 사용하지 않았다.
이번 실행은 기존 예측/추적 scene의 OCR 단일 변경 대조이지 새로운 end-to-end 추론이 아니다.

## 수치와 육안 관측

| 전체 15장, 일치 node 91개 | R8-P | R8-T |
|---|---:|---:|
| 올바른 라벨 | 62 | 82 |
| 틀린 라벨 | 0 | 1 |
| 공백 | 29 | 8 |
| 불일치/중복 node에 붙은 라벨 | 0 | 3 |

변경 대상 text-only 객체 28개는 기존에 모두 공백이었다. 이번에는 24개에 문자열이
나왔지만 그중 일치 node의 정답은 20개, 오답은 1개, 불일치/중복 검출 위 문자열은
3개다. **문자열 24개 증가를 올바른 객체 24개 증가로 보고하지 않는다.**

- `tree_1302_00036`: 정답 node 7개 중 라벨 3개 정답·1개 오답·3개 공백.
  정상 `CP`를 `CP.`로 인식했다. 같은 위치의 별도 중복 검출도 `CP`를 출력해
  상단 글자가 겹친다. 두 scale 일치가 정확성의 증명이 아님을 다시 확인했다.
- `tree_1302_00079`: 8개 라벨 모두 맞게 읽는다. 그러나 7개 연결을 여전히 내보내지
  못해 글자만 흩어져 있다. 글자 크기도 원본보다 작다.
- `tree_1302_00149`: 정답 node 10개 중 9개 인식·1개 공백. 추가 중복 검출의 `PP`,
  `Adj`가 각각 기존 글자와 겹쳐 보인다. 하단 `V`는 비어 있다.
- 나머지 12장은 실제 PowerPoint 렌더 PNG가 R8-P와 SHA까지 동일했다.
  일반 node의 bbox/문자/스타일 또는 연결을 바꿔 효과를 혼합하지 않았다.

전체 15개 native PPT를 렌더하고 원본과 나란히 육안 검토했다. 세 트리는 빈 화면에서
문자 일부가 보이는 상태로 바뀌었지만, **현재 상태는 유용한 트리 복원으로 승인할 수 없다.**
누락된 연결과 작은 글자, 겹치는 객체가 수정 비용을 남긴다.

## 고정 경계와 검증

- 원본 scene의 모든 연결/경로/방향 및 최종 native 연결이 R8-P와 정확히 같다.
- 94개 node/11개 container의 ID/역할/종류/bbox/confidence 불변.
  text-only의 label 외 shape 필드와 일반 node 전체 필드가 동일함을 대조했다.
- 따라서 추적 관계 35TP/16FP/32FN, native 관계 22TP/2FP/45FN은 그대로다.
- 15개 worker의 Python open allowlist 위반 0. OS sandbox라고 주장하지 않는다.
- 15개 PPT native 렌더/연결 binding/객체 ID 검사 통과, 래스터 객체 0.
- 전체 테스트 436 passed, 기존 known failure 2 xfailed, 기존 경고 9개.
- 새 연구 모듈/runner만 추가했다. 기존 region/enum/제품 writer 및 동결 산출물을 바꾸지 않았다.
- 단일 고정 설정 결과를 본 뒤 임계값이나 문자열을 고쳐 같은 실행을 구제하지 않았다.

## 병행 작업 통합

학습 트랙의 offline target prototype `f4c2291`을 루트 `183837f`로 통합했다.
루트에서 요청으로부터 target 전체를 재도출하여 최종 파일의 JSON 전체와 일치함을
확인했고, 33개 전용 테스트도 재실행했다. 원본 PPT에서 ellipse 11개 target이 추출되며
역할 출처는 별도로 결합된다. 이 target은 **정답 생성 전용**이며 이번 OCR 변환에는
사용하지 않았다. 이 결과로 신규 학습·일반화·제품 성능 향상을 주장하지 않는다.

## 다음 결정

1. 다른 작업은 text-only native attachment를 별도 연구 adapter/portable fixture로 검증한다.
   라벨 인식 개선과 연결 출력 개선의 효과를 분리한다.
2. 중복 owner와 OCR crop의 인접 선 유입은 별도 오류다. 문자 뒤의 점을 규칙으로
   지우거나 정답 문자열을 복사하지 않고 source evidence/객체 경쟁으로 다뤄야 한다.
3. 현재 OCR 후보는 실패와 개선을 함께 보존하는 진단 arm으로만 쓴다.
   기존 승인 버전, 미관측 holdout, 인간 수정 시간 판정은 그대로 유지한다.

산출물은 `artifacts/region-image-only-r8/text-only-ocr-v1`에 있으며, 비교는
`review/contact-2.png`와 각 개별 source/native 패널을 참조한다.
