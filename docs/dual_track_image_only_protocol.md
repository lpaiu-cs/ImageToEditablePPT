# 이미지 단독 복원: 병행 연구 및 통합 계약

## 방향 정정

프로젝트의 중심은 이미지 → 편집 가능한 PPT다. 기존 PPT/렌더 이미지/주석 정답쌍을
활용한 학습과, 이미지에서 관측한 구조를 올바르게 표현하는 연구를 병행한다.
R7/R7b는 정답 역할·소유 관계에 의존한 원인 분석이었다. 그 결과만으로 학습을
뒤로 미루거나 이미지 단독 변환의 진척을 주장하지 않는다. 기존 동결 보고서는 역사적
기록으로 보존하되, 이후 작업 순서에는 이 문서의 병행 결정을 적용한다.

사실로 인용하거나 검증 전에 코드를 무조건 합치지 않는다.

## 공통 입력·출력 경계

1. 추론 입력은 RGB 이미지와 고정된 모델/설정이다. 명시적 ROI가 필요하면 그 사실을
   별도 표시한다. 전체 이미지 자동 변환과 사람이 고른 ROI 변환을 같은 성적으로 합치지 않는다.
2. 원본 PPT, GT annotation, 정답 역할/상자/연결/제외 마스크는 학습 target과
   별도 evaluator에서만 사용한다. 추론 입력 디렉터리에는 이미지 외 GT를 두지 않고
   GT 파일 접근을 금지한 검증을 포함한다. checkpoint/설정 읽기는 허용한다.
3. 트랙 간 교환은 원본 SHA·크기·원본 픽셀 좌표·예측 객체 ID·예측 종류·신뢰도·
   관측 근거·예측 연결을 포함한 예측 결과다. 내부 포맷은 기존 `DetectorModelOutput`/
   `SlideIR`/`EmitScene`과의 어댑터를 협의하며 별도의 정답 주입 포맷으로 대체하지 않는다.
4. 기존 `NodeKind`의 열거 순서는 검출기 label index와 연결된다. 원통 지원을 이유로
   이를 임의 변경하면 checkpoint 계약이 깨질 수 있다. 새 복합 도형 메타데이터와
   관측/미지원 상태는 별도 표현으로 먼저 설계하고 변경을 상대와 협의한다.
5. 출력 가능 여부와 객체가 관측되었는지는 분리한다. 미지원 객체를 지름길 연결로
   통과시키지 않되, 그 위치를 GT로 공급해 성공으로 세지 않는다.

## 평가

- 동일하게 동결한 입력 집합과 baseline/candidate 설정·SHA를 사용한다.
- 학습 원본 슬라이드/구조와 그 렌더·증강 변종의 분할 누출을 검사한다.
- 데이터 생성기의 PIL 그림과 실제 PPT 렌더를 구분하여 결과를 보고한다.
- 학습 트랙이 정답쌍 평가 subset을 제안하고, 표현 트랙도 같은 subset에서 출력한다.
- 실제 논문 개발 그림은 추가 전이 검증으로 사용한다. 이미 본 R6/R7 그림을
  미관측 승인 집합으로 재명명하거나 Phase16 locked holdout을 임의 소비하지 않는다.
- 객체/역할·라벨·부모 관계·방향 연결의 오류와 누락, 추적 전후/native 출력 누락을
  각각 기록한다. 실제 PowerPoint 렌더를 원본과 함께 육안으로 확인한다.
- 제품 승격과 인간 수정 시간 절감은 별도 검증이다. 테스트 수나 오라클 개선으로 대체하지 않는다.

## 소통·자원·통합

- 작업 간 메시지로 초기 worktree/HEAD/수정 범위, 평가 계약, 실패 원인, 커밋/산출물,
  인터페이스 변경 요청을 공유한다. 단순 수신 확인끼리의 무한 메시지 왕복은 하지 않는다.
- GPU 학습은 학습 트랙이 사용한다. 구조 트랙은 우선 CPU 개발·테스트를 사용한다.
- PowerPoint COM 실행은 사용 시간을 메시지로 조율한다. 사용자 PowerPoint를 종료하지 않는다.
- 기존 데이터·checkpoint·동결 산출물을 덮어쓰지 않는다. 새 결과는 각자의 새 경로에 기록한다.
- 서로의 worktree 파일을 수정하지 않는다. 공통 enum/CLI 변경은 사전 협의하고,
  통합은 명시적 커밋과 동일 평가 집합의 재검증을 거친다. 아직 제품 배포/원격 push는 하지 않는다.

첫 통합 판단점은 두 트랙의 **GT 접근 없는 baseline 재현과 동일 평가 subset 합의**다.
그 이전에 어느 트랙이 우월하다거나 일반화가 확보됐다고 결론 내리지 않는다.
